## 評価で判明した実際の不具合と修正

1. **T39の初期Pythonコード自体がPyright strictで不合格**：使っていない `has_description` が `backend/benchdomain/reporting.py` にimportされていました。以前の採点ではPython単体テストしか確認せず、4試行を合格扱いしていましたが、事後にPyrightで検査すると **4試行中3試行に未使用importの型チェックエラーが残存**していました。この古い評価は型チェック込みの合格証跡から撤回します。
2. **元のコードの検査がない**：PythonとTypeScriptでは故障の注入前にそれぞれPyright/tscを実行し、先に別の型エラーがあれば評価開始前に拒否する仕組みを追加しました。修正した初期PythonコードはPyrightエラー0件です。
3. **修正後の採点が甘い**：Pythonの独立採点にPyright strictを必須追加しました。改めて実行したT39は全4試行で **単体テスト・Pyrightの双方に合格**しました。
4. **未追跡ファイルを見逃す**：以前の差分検査は `git diff --name-only` で、エージェントが新規作成してGitへ追加しなかったファイルを見落とす恐れがありました。HEADとの差分・ステージ済み・未追跡ファイルを横断して検査するよう変更し、Pythonキャッシュだけ除外しました。既存16試行のワークツリーを再監査し、不正な未追跡ソース変更がないことを確認しました。
5. **読解課題の正解判定が粗い**：T33では単なるディレクトリ名ではなく `internal/tools/helpers.go` の `target`、`internal/mcpserver/readable_relations.go` の `renderAgentRelation`、LSPメソッド `textDocument/references` まで確認するよう強化。既存の4回答も条件を満たしました。
6. **再現メタデータ不足**：今後の比較マニフェストにはCodex/Go/Node/TS/Pyrightのバージョン、MCP実行ファイルSHA-256、固定ソースのSHA-256、対象コミットを記録します。過去ログの値は事後に検算したものと区別します。
