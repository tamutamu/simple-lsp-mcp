## 実際に発見した問題と修正

| 問題（検証で確認） | 原因 | 修正 | 再検証 |
|---|---|---|---|
| `limit=2.9` や `line=9.6` が不正でも成功する | スキーマを公開するだけでサーバーでは検証せず、整数変換が小数を切り捨てていた | 全ツールで公開JSONスキーマに従った整数・範囲・型検証を行う | 異常引数は `INVALID_ARGUMENT` |
| `apply="true"`、`include_declaration="false"` が黙って無視される | 不正な文字列がGoのbool既定値で扱われた | 真偽値を厳密に確認し、意図しない書込み/プレビュー変更を防止 | 文字列を拒否し、boolの正しい入力を維持 |
| 不正な `kinds`/`severities`、重複 `related`、未知の引数が素通りする | 配列の形・値・件数・一意性と許可キーを検証していなかった | 配列型、enum、件数、一意性、入れ子の `targets`、追加の未定義引数を検証 | エラーが問題の入力キーを示す |
| 空白のみのシンボル名検索が「検索結果0件」で成功する | 空文字だけを検査し空白文字列を除外していなかった | `strings.TrimSpace` で照合 | 空白のみを `INVALID_ARGUMENT` で拒否 |
| 引数のない一覧取得が失敗する | 新しい引数検証の導入初期、未指定引数をnilマップとして扱った | 引数未指定時は空オブジェクトに正規化。明示的なJSON nullは拒否 | `list_workspace_symbols` 引数なしで結果を取得 |
| 検証器が有効なページングを「結果不完全」で失敗扱いする | ページ分割では `complete=false` と `next_cursor` が正しい契約 | ページング専用の再検証条件へ修正 | 有効な次ページ情報と不完全性表示を確認 |
| 既存のMCP発見スモークが架空の `include_source` 引数を送信していた | 以前はスキーマ外の引数を無視していたため、誤用に気づかなかった | ツール本来の `path` だけで取得するよう検証器を修正 | 新しい厳密な引数仕様でスモーク合格 |
| 追加の厳密なスキーマ指定でツール定義がサイズ上限を超えた | `additionalProperties=false` の記述増加 | 機能は維持して説明文の重複を削減 | 既存の24KiB上限テストに合格 |

入力契約の検証は `result_format=both` で実際のMCP/アプリサーバーを経由しました。独立したGo側の回帰テストでは、不正な数値・bool・enum・配列・ネスト・未知キーと、変更可能なツールの安全性を追加で確認しています。

## 手順と再現

[入力契約の50ケーススクリプト](run_50_contract_cycles.py) は、**各ケースごとに実行→期待値との照合→原因・再発防止条件の確定→同ケース再実行**を行い、どれか1件失敗したら即停止します。修正不要のケースを架空の不具合修正として数えていません。

[全22ツールの50周スクリプト](repeat_mcp_api_matrix.py) は、新しい作業環境を毎周作り、実際のgoplsとPyrightで全ツールを実行します。フォーマット、コードアクション、リネームは隔離されたファイルを本当に更新し、その変更結果まで検査します。Go/goplsの非対応 `get_declaration` は、Python/Pyrightで実際に成功することを毎周確認します。モデルAPIによる生成は呼び出しません。

```sh
# codex と simple-lsp-mcp、および gopls/pyright-langserver を導入した端末
python3 docs/benchmarks/run_50_contract_cycles.py \
  --codex /path/to/codex --mcp /path/to/simple-lsp-mcp \
  --output /tmp/simple-lsp-50-contracts

python3 docs/benchmarks/repeat_mcp_api_matrix.py \
  --codex /path/to/codex --mcp /path/to/simple-lsp-mcp \
  --output /tmp/simple-lsp-50-full-api --repetitions 50
```
