# simple-lsp MCP：製品出荷までの全タスク

対象：一般的なソフトウェア開発向けのsimple-lsp MCP。既存20ツールを維持し、正確なLSP情報をエージェントが活用できるようにする。

**全タスク必須。優先順位・段階分けなし。CIは変更・評価対象にしない。**

## 完了条件

- T01〜T56のすべてに客観的な合格証跡がある。
- Codex単体（A）とCodex＋simple-lsp MCP（B）は同じCodexモデル・effort・課題・権限・環境で比較。差分はMCP有無のみ。LSP利用は強制しない。
- 言語サーバーの起動を毎回やり直すような不自然な性能評価は行わず、長寿命セッションの実運用と起動時の挙動を分ける。
- 実行結果は成功・失敗の両方を残す。実測していない短縮率を主張しない。動作正否は実際のテストや期待仕様で独立判定。
- 個々のタスクについて、実行手順・変更内容・証跡・合否を記録し、課題が残る場合は修正・再評価する。

## 比較条件の詳細

Codex単体は、通常のコード閲覧、rg、コンパイラ、テスト、その他普段使えるCLIを自由に使う。Codex＋MCP側にも同じツールを認め、追加されるものはsimple-lspだけ。CLI gopls等が呼ばれた場合もログに残す。

課題ごとに同じスナップショットから隔離したワークツリーを作成。両条件に課題文、制限、目標、合否判定を揃える。A/B順序を入れ替えて複数回測り、キャッシュ・モデルゆらぎ・初回起動を記録する。

実測指標は、正解率、最終テスト合格、無関係な変更の有無、総所要時間、入力/出力トークン、MCP/CLI呼出数、重複検索、応答バイト量、実際のLSP使用率。平均だけでなく試行ごとの生ログと分布も残す。

**比較に不向きな課題や、LSPを使わなかった課題も削除しない。** どこで有益か・不利かを含めて製品の実態を示す。
