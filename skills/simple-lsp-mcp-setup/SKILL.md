# Set up simple-lsp-mcp

Perform the setup, not just explain commands. Use this skill only for a user's setup or repair request. Run commands with the agent's shell tool; never ask the user to copy commands that you can execute. Do not change source code, project instructions or repository dependencies.

1. **Detect the client and workspace.** Identify whether this session runs in Claude Code or Codex. Use the user's current working repository as the workspace, **not this skill's plugin installation directory**. Do not assume the OS or a bash shell on Windows. If the client cannot be identified, ask which client once. A plugin installation provides this skill; it does not guarantee the `simple-lsp-mcp` binary is installed.

2. **Find a current binary.** Inspect `simple-lsp-mcp` on PATH (Windows: `Get-Command simple-lsp-mcp`), plus any known user-local install location. Check its version and support for managed setup using `<binary> setup <client> --auto-install-lsp` (preview only). A binary that rejects the flag is too old for this workflow. If there is no usable binary:
   - If operating inside a checkout of `tamutamu/simple-lsp-mcp` with Go installed, build `./cmd/simple-lsp-mcp` from that checkout to a user-writable executable. Otherwise install the **published official release** with the bundled script `scripts/install-release.sh` (Linux/macOS) or `scripts/install-release.ps1` (Windows), located beside this skill. The scripts verify the release archive's SHA-256 checksum and install to a user-local directory; they do not require administrator rights or change PATH. Run the script directly rather than copying remote shell scripts into a pipe.
   - If the newly installed release does not yet support `--auto-install-lsp`, **stop and explain that a newer release is required**. Do not pretend the feature is available and do not use an unversioned third-party installer.

3. **Use the existing integration before creating another.** If `simple-lsp` is already connected through the installed plugin, do not also register a duplicate. A working plugin-provided MCP server with `--auto-install-lsp` needs no additional `setup` registration. Otherwise inspect the client's MCP registrations (`claude mcp get/list`, `codex mcp get/list`) and the installed plugin before changing anything.
   - If no MCP registration exists and the plugin is not providing one, execute `<absolute binary> setup <client> --apply --auto-install-lsp`. In Claude Code this uses user scope; Codex uses its regular user config. Do not edit configuration files by hand.
   - If a `simple-lsp` registration already exists but points at an obsolete binary or lacks managed mode, **show the difference before replacing it and obtain permission**. Then use the client's `mcp remove` and the setup command. Never delete unrelated MCP entries, remove a plugin, or silently overwrite custom server settings.
   - If the plugin declares an MCP but cannot launch a binary that is outside PATH, do not claim setup succeeded. Prefer arranging a correct client registration with the absolute executable path after user approval, or explain precisely that the client must be restarted with that bin directory on PATH. Do not create duplicate live servers blindly.

4. **Discover and verify real LSPs.** Run `<absolute binary> doctor --workspace <workspace> --auto-install-lsp` first; this is read-only, lists detected Go/Python/TypeScript/HTML/CSS roots and shows cached LSP paths or missing runtime prerequisites. Then choose **one existing source file for each detected language**, where practical, and run `doctor --workspace <workspace> --auto-install-lsp --probe <relative path>`. A probe installs pinned packages into the private per-user cache with `npm` or Go on first use; afterward it launches them directly by absolute path (and works offline). The first installation may need network access. No LSP installation should be attempted for languages not present in this workspace. If Node/npm or Go are missing, report exactly which prerequisite is needed; never silently install a programming runtime, change system PATH, use sudo, or modify user shell profiles.

5. **Check the connection and report evidence.** If the current session already has a working `simple-lsp` MCP tool, call `get_document_symbols` or `find_symbol` against a real project file and report whether the result is usable. If registration or binary availability changed during this session, a client restart/new conversation may be required before its MCP process can connect; clearly report `pending reconnect`, **not** `connected`. Summarize detected languages, successful/failed probes, binary location, registration status, and any exact remaining action. Do not claim success based only on the preview or on a registered but unstarted MCP.

**Client invocation:** Claude Code supports `/simple-lsp-mcp-setup` (or `/simple-lsp-mcp:simple-lsp-mcp-setup`); Codex skill invocation is `$simple-lsp-mcp-setup`, not an invented custom slash command.
